Component Strategy — foundation, custom, roadmap

2026-05-23 · Author: Gauravprakashshinde · 13 custom components specced + 5-phase roadmap
Foundation components come from Tamagui (React Native) + Angular CDK + Lucide + Geist. Custom components are the Vis-original surfaces that define the moat. This step specs the 13 most critical custom components (purpose, anatomy, states, variants, a11y) and sequences them across a 5-phase build roadmap from Phase 0.5 (foundation) through Phase 5 (lifecycle).

§2 Custom Components — 13 spec cards

Vis-original components that the brand layer depends on. Each card collapses; expand for purpose, anatomy, states, variants, a11y, interaction behavior.

1. Orb (5 tension states) brand-locked
Purpose
The signature visual — a backend-signal-driven sphere that conveys session state, recovery, and presence at a glance. Never decoration.
Anatomy
3-layer gradient: radial peach top-highlight + linear amber body + smoked-glass overlay. 3-layer peach-tinted shadow stack. --brand-locked-* tokens; never themable by accent preset.
States
At rest (no active Session in 24h) · Under load (ws.readyState === OPEN && session.active) · Peak tension (last_set.is_working && intent === 'failure') · Recovered (session.completed_at + post-session timer) · Disconnected / Stale (ws.readyState !== OPEN OR offline_queue.depth > 0).
Variants
Hero (110 × 110 px Direction 1) · Medium (56 px Direction 4 header) · Small (32 px nav corner) · X-large (150 px PR Moment cinematic).
A11y
ARIA label announces state plain-language ("Recovery: 78%, increasing" / "Session active with Brienne"). Reduce-motion: breathing loop stops; state still readable in static frame. Reduce-transparency: gradient collapses to solid amber.
Interaction
Non-interactive on most surfaces. On Recovery Orb (Direction 1 + 5 home), tap opens muscle-group breakdown sheet.
2. Connection Orb (live trainer ↔ client tension stem) brand-locked
Purpose
Visualises the live WebSocket bond between trainer and client during a Co-Edit Session. Makes the moat visible.
Anatomy
Two avatar circles linked by a horizontal tension stem (gradient amber). Stem brightness encodes presence; pulse on remote write.
States
Idle (both connected, no recent writes — stem dim amber) · Active (one party has written within 60s — stem mid-bright) · Live mutual (both wrote within 60s — stem bright + slight glow pulse) · Pulsing (800ms pulse animation on each remote write) · Disconnected (WS down — stem fades to peach tint, avatar greyed).
Variants
Header dock (Active Session, ~88 px wide) · Inline (FCM notification preview, ~44 px).
A11y
"Trainer is connected. Last edit by Brienne, 12 seconds ago." Announced via cdkAriaLive on state change; throttled to avoid spam.
Interaction
Tap → presence detail sheet (who's online, last write timestamp per party, reconnect time if applicable).
3. Equipment-Aware Logger family (6 variants) FR-8 · gesture moat
Purpose
Set logging via equipment-shaped gestures. No typing in the happy path.
Anatomy
Per variant: Cable = vertical pin-stack with draggable pin · Barbell = bar with two-sided plate-snap targets, auto-sum total · Dumbbell = number-line slider with snap increments · Machine pin-stack = same as cable · Bodyweight = silhouette + optional vest field · Kettlebell = discrete-step picker matching standard weights · Bands = colour-coded tier picker.
States
Idle (prefilled per cascade) · Active (gesture in progress) · Committed (server-ack + green check) · Queued (offline) · Stale (failed reconcile) · AI-suggested (ghost overlay visible).
Variants
All 6 share a common interface: onCommit(load, reps, source), prefill, variant: 'cable' | 'barbell' | .... Numeric-keypad fallback always available via long-press.
A11y
Logger announces "cable, slab 8, 40 kilograms" on focus. Drag gestures have keyboard equivalents (arrow keys = slab ± 1). Hit targets ≥ 44 × 44 pt. Reduce-motion: gestures still work; settle animation removed.
Interaction
Drag / snap / slide / pick / toggle. Long-press = numeric keypad fallback. First-time tap = 2s animated hint that dismisses after first successful gesture.
4. Active Session Set Row FR-1 · FR-3
Purpose
Single-row representation of a Set with prescribed-vs-actual, warm-up, failure intent, per-rep assistance, and provenance.
Anatomy
From left: warm-up checkbox · prescribed (load × reps × RPE in mono) · actual (load × reps × RPE in mono, accent-tinted on divergence) · rep-quality bar (per-rep dots: unassisted / spotter / forced) · Done toggle · provenance avatar + timestamp.
States
Empty (no actual yet) · Active (gesture in progress) · Committed (green check) · Queued (offline badge) · Conflict (Conflict Toast spawn) · Edit mode (long-press → fields editable, audit-log entry on save).
Variants
Mobile (full-width single row, 64 px height) · Tablet (wider, 56 px height). PT-attached: includes Presence Avatar Stack at right.
A11y
Reads as "Set 3, prescribed 50 kilograms 10 reps, actual 47 point 5 kilograms 10 reps." Each field independently focusable. Long-press = context menu (keyboard: Enter on focus).
Interaction
Tap any field = edit via appropriate Logger. Long-press row = Edit / Mark warm-up / Mark abandoned context menu.
5. Branch-Scope Chip (identity switcher) FR-25 · multi-role moat
Purpose
Always-visible nav element showing current identity + branch scope. Tap to switch (trainer multi-brand, owner cross-branch).
Anatomy
Pill shape · small orb glyph + brand initial + branch name. Right-side chevron when multiple options available.
States
Single-scope (no chevron, informational only) · Multi-scope (chevron, tap opens identity sheet) · Active switching (loading spinner during context swap) · All-branches view (Owner only — shows "All Branches" with brand mark).
Variants
Mobile nav corner (32 × 32 with collapsed text) · Web nav left-side (full pill with branch name) · Identity sheet variant (full list of available identities + brands).
A11y
"Current scope: Brand A, Kandivali. Tap to switch." Live region announces "Switched to Brand B, Borivali" on change.
Interaction
Tap → identity sheet appears as bottom-sheet (mobile) or dropdown (web). During active Co-Edit Session, chip is read-only (blocks switch with explanation).
6. Ghost Set Row (AI suggestion) FR-12 · FR-14
Purpose
Greyed-out, AI-suggested next Set rendered below the current Set row. Tap = accept; long-press = override.
Anatomy
Same field structure as Set row, but rendered at 50% opacity in --accent color. Confidence indicator on right (reserved --ai-confidence-low/med/high token; component lands v1.1).
States
Pending (skeleton during Claude proxy call, up to 6s cold path) · Loaded (suggestion visible) · Accepted (transitions to live Set row) · Dismissed (slides out + records override in trainer-AI-override telemetry) · Stale (suggestion arrived after user logged → self-dismiss with "stale-ai" badge).
Variants
Solo client: visible per FR-13 AI Bootstrap defaults but not for full per-set AI v1. Trainer: full AI-suggested per-set v1.
A11y
"AI suggests 52 kilograms 10 reps. Tap to accept, long-press to override." First time: inline coachmark that fades after first interaction.
Interaction
Tap = accept; long-press = open numeric override. AI-locked clients lose the override surface (autopilot mode).
7. PR Moment Composer FR-10 · FR-11 · SM-5
Purpose
Cinematic detection + share composer for personal records.
Anatomy
Full-screen overlay: amber emissive sweep (≤ 1.5 s) → headline "200 kg × 1 — your new best" → composer with 3 aspect-ratio templates (square, 9:16, 4:5) → native share-sheet trigger.
States
Detection-pending (server compute) · Detected (cinematic fires) · Composing (preview templates) · Sharing (native sheet open) · Dismissed (archived to profile, one nudge per unshared PR).
Variants
Solo: full cinematic. PT-attached: same cinematic + co-shared with trainer's PR feed. ACWR-triggered demote: no PR cinematic if recent volume spike (avoid celebration on overtraining edge).
A11y
Cinematic dismissible via tap or system back. ARIA labels on each share target. Reduce-motion: cinematic collapses to static frame.
Interaction
Detection auto-fires; user can immediately share or dismiss. Watermark toggle persists per user (default ON). Counter-metric SM-C10 if > 80% no-share — investigate composer copy.
8. Recovery Orb (per-muscle readiness) FR-35 · FR-36
Purpose
At-a-glance per-muscle-group recovery status on Client Home.
Anatomy
Central orb with 12 small chip-segments arranged radially (12 muscle groups per PRD §14). Each chip colour-coded green / amber / red based on time since last training that group.
States
All recovered (all green) · Mixed (segments multi-colored) · Heavy load (red segments warn against training that group today) · Cold start (insufficient history; "baseline-building, day X / 14").
Variants
Home (Direction 1 — large) · Progress Tab (smaller summary) · Pre-session check (shown before Active Session opens if any segment is red).
A11y
"Chest: recovered. Back: 28 hours remaining. Quads: 2 hours remaining." Tap = full muscle-group breakdown sheet with per-group last-trained and recommended-by date.
Interaction
Tap = sheet open. Long-press on a segment = jump to that muscle's history. Reduce-motion: segment fills are instant, not animated.
9. Presence Avatar Stack FR-1 · FR-25
Purpose
Overlapping avatar dots on a Set row showing who's currently editing this Set live. Provenance at the row level.
Anatomy
Up to 3 overlapping circular avatars (current actor + recent writers). 22 × 22 px each. Order: most-recent-on-top.
States
Empty (no one editing) · Single (one party present) · Multi-presence (both trainer + client) · Recent-write fade (avatar persists 30s after commit, then fades).
Variants
Set-row-level (small, inline) · Active Session header level (medium, with name labels) · Owner audit log (large with role labels).
A11y
"Brienne is editing. Last edit by Samwell, 8 seconds ago." Throttled live region updates.
Interaction
Tap stack = presence-detail sheet (who's online + last write per actor + reconnect time).
10. Conflict Toast FR-1 LWW
Purpose
Non-modal notification when a remote write overwrote yours. Last-write-wins surfaced calmly.
Anatomy
Bottom-sheet-like single-line toast: avatar of overwriter + "[Trainer] overwrote your value 47.5 → 50" + Undo button + dismiss.
States
Visible (8 s default) · Tapped Undo (sends revert, decrements server version) · Dismissed (toast slides out, write stands).
Variants
Single-conflict (most common) · Batch (multiple overwrites in same drain — collapsed into "5 writes overwritten" with expand).
A11y
Live region announces overwrite. Toast is focusable via screen reader. Undo is a hard-target button ≥ 44 × 44 pt.
Interaction
Auto-dismiss 8 s. Tap = persistent (don't auto-dismiss). Tap Undo = revert via server-stamped order; recipient sees their own Conflict Toast.
11. Risk Banner (ACWR alert) FR-37
Purpose
Trainer-side alert when a client's Acute:Chronic Workload Ratio crosses risk thresholds.
Anatomy
Inline banner on Trainer client-detail screen: amber tint (ACWR > 1.5) or red tint (ACWR > 2.0) + 1-line summary ("Samwell: ACWR 1.7 — injury-risk zone") + primary action ("Apply deload to next session") + dismiss.
States
Amber (consider deload) · Red (auto-deload suggestion fires via Ghost Set Row at 70% prescribed loads) · Cold-start ("baseline-building, day X / 14" — suppressed for first 14 days per PRD).
Variants
Inline banner (default) · Push notification (FCM, single client) · Dashboard summary (across clients in Trainer Today).
A11y
"Risk alert for Samwell. ACWR 1.7 — injury risk zone." Action button is primary focus target. Tone: "consider deload," never "you're overtraining."
Interaction
Primary action applies deload to next session (Ghost Set Row updates). Dismiss = banner hidden until next ACWR recompute (weekly).
12. Session Recovery Sheet abandonment flow
Purpose
On next open after a Session was abandoned (last activity > 30 min ago without explicit End), offer Resume or Discard with partial-Set preview.
Anatomy
Modal sheet: title "Unfinished session from 47 minutes ago" + 2-3 partial Set rows preview + Resume CTA + Discard secondary.
States
Pending (just opened) · Resume tapped (returns to Active Session with state intact) · Discard tapped (confirmation dialog, then partial Sets archived as abandoned).
Variants
Short-abandon (< 2 h ago) · Long-abandon (> 24 h ago — defaults to Discard preselected).
A11y
Modal traps focus. Resume + Discard both hard-target buttons. Reads as "Unfinished session from 47 minutes ago. 3 partial sets. Resume or discard?"
Interaction
Modal blocks Active Session entry until choice made. Discard has a confirmation step to prevent fat-finger data loss.
13. Empty States set (per surface) cross-surface
Purpose
Surface-specific empty-state illustrations + copy + next-action CTA. 21st-magic won't get these right by default.
Anatomy
Centered: small orb glyph + 1-line plain-language heading + 1-line context (why empty) + primary CTA + optional secondary link.
Variants
Empty Logger (no exercise selected — "Pick an exercise to start logging") · Empty PR feed ("Your PRs will appear here") · Empty branch dashboard (Owner — "No data yet — branches will populate as members join") · Empty client list (Trainer — "Your roster is empty. Accept a client request to begin.") · Empty trainer roster (Staff — "No trainers active at this branch.") · Empty audit log (Owner — "No entries match your filter. Broaden range?").
A11y
Each empty state has descriptive ARIA + a hard-focusable CTA. No "ghost" decoration with no action.
Interaction
Primary CTA always navigates to the resolution path (e.g. Empty Logger → exercise picker).

§3 Implementation Strategy

How custom components are built on top of foundation, what guardrails apply, and how the 21st-magic workflow integrates.

  • Token discipline. Every component imports tokens through Layer B (--accent, --brand-locked-*). Components in the brand-locked allowlist (orb, wordmark, PR-watermark) may import Layer A --vis-amber-* directly. ESLint no-restricted-syntax blocks raw hex in /components/**.
  • Composition over inheritance. Custom components compose Tamagui primitives — don't fork the library. If a primitive can't be styled via token, build a sibling custom component rather than overriding.
  • 21st-magic workflow. Every new component: (1) 21st_magic_component_inspiration reference, (2) 21st_magic_component_builder or _refiner scaffold, (3) 5-step "adapt to Vis tokens" checklist (hex → tokens, shadow stack, brand-ref PNG check, WCAG contrast, light + dark screenshot diff), (4) merge.
  • Accessibility default. Tamagui + Angular CDK provide ARIA primitives; Vis-custom components ship explicit ARIA labels. CI gate via pa11y-ci + Node wcag-contrast script.
  • State machine per component. Every component with > 2 states has a documented state diagram. UI state is derived from backend signals where possible (orb states tied to ws.readyState / session.active / offline_queue.depth).
  • Cross-platform parity. Wherever a component appears on both RN + Angular (KPI cards, Empty States, Branch-Scope Chip on Admin Web), the contract is the same: same props, same a11y labels, same state names. Visual rendering differs per platform but semantics stay identical.

§4 Implementation Roadmap

5 phases. Each gated by the SM it unlocks. Phase 0 + 0.5 = foundation (per step-06). Feature work starts Phase 1.

Phase 0 + 0.5

Foundation

  • tokens.ts workspace package (Layer A + B)
  • Tamagui + Babel plugin (optimize: true)
  • Angular CDK + Tailwind config (preflight scoped)
  • Lucide ports both sides
  • Geist + Geist Mono self-hosted
  • Reanimated + Gesture Handler + blur + Skia on EAS dev client
  • WCAG contrast CI · ESLint guardrails
  • 6 gesture maps documented
Gates: nothing yet — pure infra.
Phase 1

Active Session core (the moat)

  • Orb (5 states + animations)
  • Connection Orb (live presence + pulsing)
  • 6 Equipment-Aware Loggers
  • Active Session Set Row + Provenance line
  • Presence Avatar Stack
  • Conflict Toast
  • Ghost Set Row (placeholder; AI confidence chip reserved v1.1)
  • Rest timer
Gates: SM-1 WALS, SM-3 Co-Edit ≥ 25%, SM-C6 set-save p95.
Phase 2

Sharing + PR loop

  • PR Moment cinematic
  • PR Card composer (3 aspect ratios)
  • Native share-sheet integration
  • Vis watermark + per-user toggle
Gates: SM-5 PR-Card share ≥ 30%; SM-C10 no-share < 80%.
Phase 3

Recovery + risk

  • Recovery Orb (12 muscle segments)
  • Per-muscle weekly set-count chip
  • Risk Banner (ACWR amber + red)
  • FCM ACWR push
  • Progress Tab (line charts + heatmap + sparkline)
Gates: SM-2 D7 retention ≥ 35%; SM-7 trainer-monitoring ≥ 50%.
Phase 4

Multi-role + Admin Web

  • Branch-Scope Chip (identity switcher)
  • Owner KPI cards + sparklines
  • Branch dashboard tables (solid surfaces)
  • Audit-log query interface
  • Trainer Leaderboard
  • Staff CSV import + PT activation + payment log
Gates: SM-7 + SM-8 ≥ 2/brand/week.
Phase 5

Lifecycle + empty states

  • Onboarding Questionnaire (shared component, path-aware shell)
  • Session Recovery Sheet (abandonment)
  • Empty States set (6 surfaces)
  • Plan-block expiry FCM cadence
  • PT-relationship state machine UI
Gates: SM-6 onboarding ≥ 60%; SM-C8 no-log < 50%; SM-4 Solo D30.
