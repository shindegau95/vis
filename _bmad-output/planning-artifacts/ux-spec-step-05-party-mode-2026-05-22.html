Where the three agents agreed

Strong consensus

  • Defer the themable accent UI to v1.1. John: no FR-coverage, no SM lift, real v1 test-matrix burden. Winston: needs Layer A/B token system + WCAG contrast CI gate before any preset ships. Sally: 6 presets spans 270° of the hue wheel — sage / plum will fight the locked amber orb. Compromise: ship the two-layer token architecture day 1 so v1.1 lands without re-architecture; defer preset UI.
  • Two-layer token architecture (Winston). Layer A = raw (--vis-amber-primary, --preset-ember-500); never consumed by components. Layer B = semantic (--accent, --accent-on, --accent-muted, --accent-emphasis, --brand-locked); what components reference. Switching preset rewrites Layer B → Layer A. Shared tokens.ts as workspace package consumed by RN ThemeProvider + Angular CSS variables.
  • Accent on non-text affordances only. Fills, icons ≥ 24 px, chart strokes, focus rings. Text uses --accent-on precomputed per preset, validated at token-build time with a contrast script (fail CI if < 4.5:1). No preset touches body text colour. Hard architectural constraint.
  • Prune Pattern Transfer to FR-anchored rows. John: every row must answer "Which FR? Which SM?" — kill anything blank. Sally: "Calm holistic dashboard" too vague; "Trainerize ref-to-beat" is a competitive note not a pattern; "Line-chart rendering" duplicates the Apple Health row. Result: 10 rows → ~6 FR-anchored rows.
  • Demote Bevel. Sally: holistic dashboard + biological-age earned-metric don't map; only the AI confidence display transfers. Winston: even the confidence chip should defer to v1.1 because calibrated probability + dismissal feedback loop needs new FR coverage. Recommendation: keep Bevel on the inspiration list but scope strictly to "AI suggestion confidence pattern (reserved for v1.1)."
  • Elevate Motra to #1. Sally: strongest fit for Vis context. Compact Set row with inline RIR/RPE is direct adoption for the Active Session view.
  • Add Strong app to inspiration list (Sally). Gold standard for compact set rows, rest-timer-as-ambient, and one-handed thumb operation. Skipping it means re-deriving the same patterns worse.
  • Add Linear / Figma multiplayer cursors (John, Sally). Directly serves SM-3 Co-Edit. Real-time presence model + cursor pattern is exactly what the Connection Orb needs visual ancestry for.
  • Specify Apple Health interaction, not just chart style (Sally). What transfers: pinch-to-zoom timeline, tap-a-point-for-callout, swipe between metrics on the same axis. Without this, the row is decoration.
  • Add two anti-patterns (Sally, John). Strava-style social feed / leaderboards — Vis is private 1:1 coaching, not feed; trips SM-5 if PR-share feels like leaderboard chore. Whoop metric overload on home — trips SM-2 D7 by burying the one number that matters.
  • Fix Mindbody/Glofox principle citation (Sally). Currently cites "cross-app brand parity" but the real violation is Emotional Principle #4 (Presence without surveillance — dense ops UI = surveillance posture) plus Principle #1 (Earned over celebrated — admin chrome over member story).
  • Motra recovery shading needs a backend signal (Winston). recovery_score (0–100) currently has no FR. Options: (a) compute client-side from HealthKit / Health Connect read-only HRV + sleep already in scope, or (b) add GET /recovery endpoint. Flag to PM before shipping the visual.

Each agent's full take

🎨 Sally — UX Designer interaction grammar · gesture · pattern transfer

1. Four inspirations — two weak. Bevel is mis-cast: only the AI confidence display transfers; holistic dashboard + biological-age don't map. Demote to "AI-suggestion confidence pattern only." Apple Health is right but underspecified — name the interaction (pinch-zoom timeline, tap-for-callout, swipe between metrics). Motra is the strongest, should be #1, not #3. Missing: Strong app (gold-standard compact set rows, ambient rest timer, one-handed thumb operation). Add it. Also add Linear for the workspace switcher / branch-scope chip lineage.

2. Pattern transfers — three hollow. "Calm holistic dashboard" — vague. Cut or rename to "single hero metric + 2 supporting tiles, no grid-of-12." "Trainerize ref-to-beat" — competitive note, not a UX pattern; move to anti-pattern or strategy section. "Line-chart rendering" — duplicates Apple Health row; merge.

3. Anti-pattern citations. MyFitnessPal → Dignity ✅. Mindbody/Glofox → cross-app brand parity ⚠️ weak; real violation is Presence without surveillance + Earned over celebrated. Bodyspace → Presence without surveillance ✅. Fitbod → Earned over celebrated ✅. Missing: Strava social pressure / leaderboards — call it out before someone pitches a feed.

4. Six accent presets — too many, hue spread incoherent. 270° of color wheel; orb stays amber while user picks plum is two brands fighting. 4 presets in warm-to-neutral range — Tangerine, Ember, Rust gold, Slate teal. Drop sage and plum. Cardinality 4 also fits a single row of swatches in Profile without wrapping.

📋 John — Product Manager PRD intent · SM coverage · scope discipline

1. Inspiration → SM mapping. Bevel ties to SM-2 + SM-6 (one number that matters → D7 + onboarding). Apple Health ties to SM-1 + SM-7 (hierarchy → trainer morning sweep). Motra ties to SM-5 (PR celebration → share trigger). "Own prototype" doesn't move a number — replace with Linear/Figma multiplayer to serve SM-3 Co-Edit, currently under-served.

2. User-themable accent — defer to v1.1. Scope creep, no SM lift. FR coverage: zero. 6 presets × light/dark × accessibility = real test burden. Conflicts with PRD's tone-locked brand surface claim. Defer behind a feature flag; if user insists on v1, demand a named FR (FR-Personalization-01) + target SM. No FR, no ship.

3. Pattern Transfer Table — 10 is 2 too many. Audit every row: which FR + which SM? Blank either column → cut.

4. Anti-patterns — add 2. Strava social-feed gravity (SM-5 trip). Whoop metric overload on home (SM-2 D7 trip). Name them so nobody pitches a feed or a metric-firehose dashboard later.

🏗️ Winston — System Architect tokens · theming · WCAG · RN×Angular parity

1. Accent across RN + Angular — two-layer token system. Layer A raw (--vis-amber-primary, --preset-sage-500); never consumed by components. Layer B semantic (--accent, --accent-on, --accent-muted, --accent-emphasis, --brand-locked); what components reference. Switching preset rewrites Layer B → Layer A. Angular: :root[data-accent="sage"]. RN: ThemeProvider + useTheme(); shared tokens.ts workspace package.

2. WCAG AA is the real risk. Sage green and slate teal on warm ivory will fail 4.5:1 body text; dusk plum on dark fails similarly. Accent on non-text affordances only (fills, icons ≥ 24 px, chart strokes, focus rings). Body text uses --accent-on precomputed; CI fails if < 4.5:1. Hard architectural constraint — write into PRD now.

3. Brand-locked naming. Reserve --vis-amber-* exclusively for locked surfaces (orb, wordmark, PR watermark). User-themable surfaces read --accent. Two namespaces, zero ambiguity. Rename anything currently mixing the two before save.

4. Bevel AI confidence display — scope add. Needs calibrated probability + dismissal feedback loop persisted to backend (no FR yet). Defer chip to v1.1; reserve --ai-confidence-low/med/high tokens so visual lands without re-architecture later.

5. Motra recovery shading — needs backend signal. recovery_score (0–100) has no FR. Either compute client-side from HealthKit/Health Connect HRV + sleep already read-only synced, or add GET /recovery endpoint. Flag to PM before shipping the visual.
