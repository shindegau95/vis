§1 Defining Experience

The single most-frequently-performed action and the loops that surround it.

The Vis core loop, expressed once:

"Open the app at the equipment → see what's next → log without typing → done."

Everything else is a path to or a consequence of this loop. The single most-frequently-performed action is logging a Set on an Equipment-Aware Logger (FR-8). The discipline: one touch + one gesture in the common case; never typing in the happy path.

Four secondary loops form around the core:

  1. Pre-session loop (Trainer) — author + assign program → review client adherence + ACWR alerts → coach.
  2. Active-session loop (Trainer + Client) — co-edit Sets in real time, prescribed-vs-actual, warm-up flag, failure intent, assistance tagging.
  3. Post-session loop (Client) — Progression Index update, e1RM graph tick, Recovery Orb refresh, PR detection.
  4. Ops loop (Staff + Owner) — member CSV → PT activation → payment logging → reminder cadence → branch dashboards.

If the Equipment-Aware Logger action breaks, every loop breaks. If it works, the moat compounds.

§2 Platform Strategy

Three apps, two paradigms (touch-mobile + browser-dense), one brand language.

App Platform Primary input User posture
Client App React Native (iOS + Android) touch, single-hand thumb arc mid-session, sweaty, distracted, sometimes offline
Trainer App React Native (iOS + Android) touch, two-hand authoring + one-hand in-session high context-switch rate (8 sessions/day)
Admin Web Angular (browser) mouse/keyboard, dense tables, dashboards seated at front-desk or office; spreadsheet-replacement posture

Cross-app constraints

  • Offline-first mandatory on Client + Trainer mobile apps. NFR §7.5 idempotency UUID is the architectural lever; UX renders queued-vs-committed state per Set row.
  • Online-only acceptable on Admin Web; ops surfaces don't need disconnection survival.
  • WebSocket transport for Co-Edit Sessions on mobile; polling fallback at 10 s.
  • Real-time UI on Admin Web not required v1 — dashboards refresh on page load or explicit reload.
  • Light + dark theme parity v1 across all three apps (quality bar, not moat).
  • WCAG 2.1 AA on Admin Web; mobile equivalent = VoiceOver/TalkBack labels on every interactive element + 44×44 pt hit targets + reduce-motion/reduce-transparency fallback (NFR §7.7).
  • Cold start ≤ 2.0 s mid-tier Android (Pixel 6a / Galaxy A54). Set-save → server commit p95 ≤ 250 ms.
  • i18n structured day 1 (English-only translation v1, kg/lb + m/ft toggles, per-locale dates, time zones, INR-ready data model, RTL stub).

§3 Effortless Interactions

Where the user feels zero cognitive load. Nine surfaces.

1Logging a Set on the equipment in front of you.
Tap exercise → logger pre-loads last-used load → adjust by gesture (drag pin, snap plate, slide slider) → tap Done. No typing. No remembering last week's weight. Voice fallback for trainer in-session if hands occupied.
2Knowing what to do next.
Today's Plan card on Client home. Today's schedule on Trainer home. No menus. The next session is always one tap away.
3Switching identity context.
Trainer multi-brand: tap branch chip in nav → identity swaps. Owner cross-branch: same chip → drill-down or aggregate. Zero menu-diving.
4Reflecting prescribed-vs-actual.
Trainer types prescribed; client lifts actual; UI shows both with a divergence cue (subtle tint). Neither party reformats anything.
5Reading recovery status.
Recovery Orb on home colour-codes per-muscle readiness from last session — green / amber / red — at a glance.
6AI suggestion acceptance.
Ghost overlay shows next-prescribed load on the logger. One tap = accept. Long-press = override. ai_locked autopilot toggle removes the override surface for clients who want full automation.
7Detecting a PR.
Set save → PR detection runs server-side → cinematic moment screen fires automatically. User doesn't compute or trigger anything.
8Reconciling offline writes.
Connection Orb shows offline state without alarm. Reconnect = 5 s drain, no user intervention.
9Onboarding via QR (gym path).
Front-desk QR → sign in → roster matched → trainer browse → first session pre-loaded. No manual data entry beyond the Questionnaire.

§4 Critical Success Moments

The make-or-break moments that decide whether the user stays. Each maps to a PRD success metric where it exists.

1First Set logged (D0). SM-C8
Onboarding → first exercise → first Logger touch. If this fails (logger > 200 ms, crash, requires typing), the user churns same-day. SM-C8 watches new-signup-no-log > 50%.
2First Co-Edit moment (UJ-1, D1–D7 PT-attached). SM-3
Trainer + Client both editing the same Set on two devices. The first time they see the other side's write appear with the Connection Orb pulsing — that's the moat moment. SM-3 ≥ 25% of Trainer-led Sessions with bidirectional Co-Edit writes by D90.
3First PR detection (D7–D30). SM-5
Working set clears prior e1RM → cinematic Moment screen fires → composer offers share. If it lands well, we get social-channel reach. SM-5 PR-card share rate ≥ 30% by D180.
4First reconcile after offline drop. Gates SM-2
Mid-session WebSocket disconnect → app shows offline banner without alarm → reconnect drains queue → no data lost. "8 sets just vanished" = product trust evaporates. No SM directly, but it gates SM-2 D7 retention.
5First trainer-AI-accept. SM-C5
Trainer sees ghost overlay; one-tap accept feels right; suggestion was sane. If the first AI suggestion is laughable, trainer disables AI for that client forever. SM-C5 watches trainer-override rate > 70%.
6First PT-renewal decision (D28-ish).
PT block approaching expiry; client's Progression Index trending up; trainer's renewal nudge is the moment. Vis success = renewal; failure = client lapses to general member. Drives the underlying business model.
7Branch-switch identity context (Trainer multi-brand).
When a Solo+Gym trainer switches from Brand A morning session to Brand B afternoon, the branch-scope chip must obviously reflect the new context. A wrong-scope write here is a data-bug at the interaction layer.
8Owner morning glance (daily). SM-7 / SM-8
One screen shows: yesterday's revenue, branch-by-branch active count, trainer leaderboard delta, churn-risk list. If owner has to drill into 7 tabs, the dashboard fails its job.

§5 Experience Principles

Five guiding rules. Every UX decision must serve at least one; if it violates one, it needs a stated reason.

1No typing in the happy path.
Numeric keypad exists as fallback only. The default flow uses gesture (drag, snap, slide, tap). Survives even when v2 ships voice input as a Tier-1 modality.
2Visible presence + provenance over silent state.
When two parties (Trainer + Client) touch the same data, both see who-did-what immediately. The Connection Orb is the canonical surface. Silent state is a bug.
3Earned over celebrated.
PR Moments use cinematic restraint, not gamified confetti. Streaks are heatmaps, not loud badges. The orb dignifies progress; it never patronizes.
4One icon, layered semantic.
The orb is the only repeating visual motif across all three apps. Each tension state ties to a backend data source (per Challenge 12). Decoration without data is forbidden.
5Branch-scope chip always present, always glanceable.
Multi-role / multi-brand / multi-branch identity is a structural feature of the Vis user. The current scope must be inspectable in ≤ 200 ms of eye-travel from any screen.
+Bonus (operational): Offline-first means the orb doesn't lie.
If the device is queued, the orb says queued. If the WebSocket dropped, the orb says disconnected. Trust in the orb's state is trust in the app.
