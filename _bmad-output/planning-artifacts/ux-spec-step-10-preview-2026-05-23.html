Edge cases:
  • Both sides offline simultaneously → both queue locally; reconciliation on whoever reconnects first; conflicts surface as one-line Conflict Toast.
  • Reconnect takes > 30 s → app remains usable in offline mode; Connection Orb stays "Disconnected"; Set row badges stay "queued" until reconnect.
  • App force-closed during offline → queue persists in local storage; on next open, Session Recovery Sheet offers "Resume" with partial-set preview.
  • Write fails server-side (idempotency UUID rejected as duplicate) → no double-write; UI confirms prior commit silently.
  • Network restored but server rejects write (e.g. validation) → set row badge transitions to "stale" with retry / dismiss options.

Components exercised

Connection Orb (Disconnected / Stale state) · Set row "queued" badge · Set row "committed" badge · Idempotency UUID infrastructure · Conflict Toast · Session Recovery Sheet.

§ Journey Patterns + Flow Optimization Principles

Reusable patterns that recur across the six journeys, plus the optimization rules they imply.

Reusable patterns

PatternRecurs inWhat it does
Branch-Scope Chip identityUJ-1 · UJ-4 · UJ-5Always visible in nav. Single source of truth for "who am I, where am I." Tap = identity sheet. Trainer multi-brand and Owner cross-branch both use this.
Connection Orb presenceUJ-1 · UJ-6Visible link between two parties on the same Session. Tension stem pulses on every remote write. Tints to "Disconnected / Stale" on network loss.
Provenance lineUJ-1 · UJ-4 · UJ-6Set row badge = actor avatar + timestamp. Visible within 500 ms of write commit. Fades after 30 s of no further writes.
Prefill cascadeUJ-1 · UJ-2 · UJ-3 · UJ-4Logger never opens empty. Order: AI ghost → trainer prescribed → last-Set → AI bootstrap → empty + keypad.
Cinematic moment post-server-confirmUJ-1 · UJ-2PR Moment fires only after server confirms detection. Optimistic celebrations forbidden (Emotional Principle 3).
Queued vs committed visual stateUJ-6Set-row badge changes: "queued" (local ack) → "committed" (server ack) → "stale" (failed reconcile). Tied to (ws.readyState, offline_queue.depth, last_server_ack_at) tuple.
Non-modal conflict surfacesUJ-1 · UJ-6Conflict Toast is a one-line non-blocking notification. Never modals mid-Set. Tappable revert; ignored = remote write stands.
FCM notification → context restoreUJ-3 · UJ-5Tapping a push notification (trainer-request, ACWR alert, plan-block expiry) opens app to the exact relevant surface with branch scope already correct.

Flow Optimization Principles

  1. Minimise steps to first Set logged. UJ-3 onboarding has 11 steps; first Set should follow within 24 h of completion (SM-6 + SM-C8). Onboarding fields skippable where not strictly required.
  2. Reduce cognitive load at every decision point. UJ-4 identity switch presents the chip — not a settings menu dive. UJ-5 owner dashboard surfaces anomalies (Borivali churn) without requiring a query first.
  3. Provide visible progress at every step. UJ-2 PR detection shows running compute; UJ-3 onboarding shows "X of 10 fields"; UJ-6 reconcile shows "queued / committed" per Set row.
  4. Create moments of delight only when earned. UJ-1 + UJ-2 PR Moment fires only on server-confirmed detection. No celebratory animation on optimistic write.
  5. Handle edge cases gracefully. Every journey above lists 4–6 edge cases. The UI degrades to a calm explicit state — never a silent failure.
  6. Persist state across drops. UJ-3 abandons mid-Questionnaire = resume from last field. UJ-6 force-close offline = Session Recovery Sheet on next open. State trust > re-derivation.
