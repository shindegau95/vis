Vis — three-app fitness platform built around one live moment

Author: Gauravprakashshinde · Date: 2026-05-23 · Status: Complete · 14 / 14 steps
Two phones, three feet apart, both editing the same Set live. The trainer drags the cable pin to 40 kg; the client sees it update before they grip the handle. Either taps Done; the other side sees the green check land within 500 ms. No typing. The Set knows who wrote it. Everything in this spec serves that moment — the Logger gesture vocabulary, the Connection Orb pulse, the Provenance line, the multi-role identity model, the cinematic restraint. All locked.

§1 Executive Summary

Three load-bearing assertions + two anchor priorities locked.

Anchor priorities (locked in step-05 party-mode)

Anchor 1 · Equipment-Aware Logger fidelity (6 gestures) Anchor 2 · Real-time co-edit + multi-role context

Three load-bearing assertions

  1. Primary user pain = remembering + inputting progression. Visual equipment-aware logging is the differentiator; the orb is a brand surface, not the moat.

§2 Core User Experience

The core loop. Five experience principles. Twelve design challenges (ordered by structural weight).

Core loop — multi-actor first

"Trainer and client both touch the same Set, in the same room, on two devices. The Set knows who wrote it."

Solo-lifter framing is a secondary loop, not the headline. The Cluster-A competitors (Fitbod, Hevy, Strong, Motra, Bevel) all ship a polished solo logger; Vis's defensible wedge is the multi-actor moment plus the multi-role context.

Five core experience principles + 1 operational

  1. No typing in the happy path. Verifiable: zero keystroke events on Set log.
  2. Visible presence + provenance over silent state. Verifiable: actor avatar + timestamp on every co-edited row within 500 ms.
  3. Celebration UI only fires post-server-confirm. Verifiable: no animation on optimistic write.
  4. Orb state changes are backed by a named signal. 5 states each tied to a backend tuple.
  5. Branch-scope chip always present, always glanceable. Inspectable in ≤ 200 ms of eye-travel.
  6. (Operational) Offline-first means the orb doesn't lie. Truth source = (ws.readyState, offline_queue.depth, last_server_ack_at).

§3 Desired Emotional Response

Three primary emotional goals. 14-stage journey. 5 emotional design principles.

Three primary emotional goals

  1. Quiet competence. Capable, in-control. The equipment is theirs to command. Earned, owned. Not flattered.
  2. Coached presence + Solitary focus. PT-attached: accompanied without managed. Solo: focused without lonely.
  3. Earned trust in the tool. The orb doesn't lie. Data doesn't disappear. AI doesn't condescend.

5 emotional design principles

  • Earned over celebrated.
  • Calm under degradation. Anxiety is a bug.
  • Dignity in failure.
  • Presence without surveillance.
  • Recognition over reset.

§4 UX Pattern Analysis & Inspiration

5 inspirations (Motra · Strong · Apple Health · Linear/Figma · Bevel deferred). 6 anti-patterns. v1.1 user-themable accent reserved.

Inspirations (ordered by transfer fit)

  1. Motra — compact Set row with inline RIR/RPE; recovery-aware programming. Strongest fit.
  2. Strong app — rest-timer-as-ambient; one-handed thumb operation.
  3. Apple Health — chart interactivity (pinch-zoom, tap callout, swipe between metrics); sparkline-on-card.
  4. Linear / Figma multiplayer — cursor presence model → Connection Orb tension stem; workspace switcher → Branch-Scope Chip.
  5. Bevel — AI suggestion confidence pattern only; component reserved for v1.1.

6 anti-patterns to avoid

  1. MyFitnessPal data interrogation
  2. Mindbody / Glofox dense ops UI
  3. Bodyspace bro-culture aesthetic
  4. Fitbod gamified celebration
  5. Strava social feed + leaderboards
  6. Whoop metric overload on home

User-themable accent — deferred to v1.1

Token plumbing ships day 1 (two-layer system). UI lands v1.1 with 4 presets: Tangerine (default), Ember red, Rust gold, Slate teal. Brand-locked surfaces (orb, wordmark, PR-watermark) stay amber regardless. WCAG contrast CI gate.

§6 Defining Core Experience

The 3 irreducible parts of the moment + 8 measurable thresholds + mechanics.

The 3 irreducible parts

  1. The Logger gesture. Drag the cable pin. Snap a plate. Slide the dumbbell rack. No typing.
  2. The Provenance line. Set row knows which actor wrote each field, when. Avatar + timestamp within 500 ms.
  3. The Connection Orb pulse. Tension stem between two amber spheres pulses on every write.

8 measurable success thresholds

  • Set save → server commit p95 ≤ 250 ms online
  • Set save → local-queued ack ≤ 100 ms offline
  • Logger first-contentful render ≤ 200 ms
  • Other side's write on screen ≤ 500 ms
  • Zero keystrokes in happy path
  • Provenance visible within 500 ms of commit
  • Connection Orb pulse completes < 800 ms
  • AI accept ≤ 1 tap (long-press override)

§7 Visual Design Foundation

Two-layer token system. Geist + Geist Mono. 4 px spacing grid. WCAG AA contrast gate.

Two-layer token system

  • Layer A — Raw amber: --vis-amber-* (primary, deep, ember, soft, highlight, shadow, glow). Never consumed by components.
  • Layer B — Semantic themable: --accent, --accent-on, --accent-muted, --accent-emphasis. All themable surfaces consume these.
  • Layer B — Brand-locked: --brand-locked-primary/deep/shadow. Orb, wordmark, PR-watermark. Never overridden by accent preset.

v1.1 preset palette (4 presets, computed for AA contrast)

  • Tangerine (default)
  • Ember red

  • Slate teal

§11 UX Consistency Patterns

7 pattern categories: buttons · feedback · forms · nav · overlays · empty · search.

  • Button hierarchy: primary / secondary / ghost / destructive / disabled. One primary per screen.
  • Feedback: toast (ephemeral, auto-dismiss), banner (persistent contextual), inline (per-field validation). Calm under degradation.
  • Forms: single column, label above field, validate on blur, error red border + plain helper text.
  • Navigation: mobile bottom-tab (4 max), web left sidebar; Branch-Scope Chip always visible; FCM tap → context restore.
  • Overlays: modals for blocking decisions only; sheets for contextual choices; no modal stacking.
  • Empty + loading: skeleton when structure known, spinner only otherwise. Empty states always carry a CTA.
  • Search + filter: 200 ms debounce; filter chips scroll horizontally sticky under nav.

§12 Responsive Design + Accessibility

Mobile RN = platform-native (no breakpoint adaptation). Admin Web = 4 breakpoints, desktop-primary. WCAG 2.1 AA gate.

Admin Web breakpoints

  • Mobile fallback (320–767 px) — read-only
  • Tablet (768–1023 px) — front-desk staff
  • Desktop primary (1024–1439 px) — owner morning glance
  • Wide desktop (1440+ px) — whitespace, not more density

WCAG 2.1 AA — what Vis ships

  • ≥ 4.5:1 body text contrast (CI-gated)
  • ≥ 3:1 large text (Display + Title)
  • Keyboard navigation + screen-reader labels on every interactive element
  • Hit targets ≥ 44 × 44 pt mobile; ≥ 32 × 32 web
  • Reduce-motion + reduce-transparency support across all custom components
  • Color blindness: critical state distinctions never rely on color alone
  • Privacy ∩ a11y: health data never announced via VoiceOver outside the relevant surface
